Inside each parallel worker

car_info, quotation, service and locator each run this small loop in their own subgraph, with a private scratchpad. Only the result comes back to the main graph.

The flow in words

  1. HumanMessage → State. The customer's message is added to messages.
  2. supervisor. One Gemini call returns the intents, the slots (shared details plus a list of cars) and an escalation flag. Python merges the slots with the remembered ones and resets the per-turn fields.
  3. router. ① A person is needed (flag, or 2+ failed turns in a row) → escalate. ② A required detail is missing → clarify, which asks one question and ends the turn. ③–⑤ Otherwise the intents become agents and are split.
  4. Parallel agents. Each read-only agent gets its own copy (recent messages, summary, only its cars) and runs its loop at the same time as the others. Results join in agent_outputs; after_agents waits for all.
  5. Action agents. lead, then support, one at a time. Each sees the others' results, runs its tool loop, and pauses at ask_user before saving anything. save_output stores its result and hands over to the next one.
  6. composer → guardrail. One reply from every finding, in a fixed order. Any ₹ or km figure not found in a tool result sends it back once; a second failure gives a safe reply.
  7. summarize → END. Past 20 messages, older ones are folded into the summary. After END the State is saved to a file.
